# alinaecosin.ru — сайт Алины Сингизовой

Сайт-визитка нутрициолога: главная, магазин и документы. На выходе обычная
статика — что лежит в корне репозитория, то и отдаётся браузеру. Но **корень
собирается из `src/`, и править его руками нельзя**: следующая сборка затрёт.

**Пуш в `main` выкатывает сайт на боевой домен.** GitHub Pages публикует эту
ветку напрямую, изменения видны на alinaecosin.ru примерно через минуту.
Отдельного шага деплоя нет, ветки-стейджинга нет. Домен привязан файлом
`CNAME` — не удалять и не переименовывать. Рядом лежит пустой `.nojekyll`:
он выключает Jekyll, который Pages иначе прогоняет поверх уже готового HTML.
Пользы от Jekyll здесь нет, а сборка от него падает. Тоже не удалять.

Имя репозитория `EcosinPregnancy` осталось от самой первой версии и текущему
содержимому не соответствует. Не путать с «Диспетчерской» — это отдельный
сервис на alinaecosin.store, который принимает заявки с формы и отдаёт каталог
магазина; живёт он в другом репозитории.

## Как собирается сайт

Шапка, меню, подвал и счётчик Метрики нужны на каждой странице. Пока страниц
было две, копипаст терпели; на пятнадцати правка одного пункта меню
превращается в пятнадцать правок, из которых две забудешь. Поэтому в `tools/`
лежит маленький сборщик на Python — без зависимостей, без Node и без Actions.
Деплой от этого не изменился: собранная статика коммитится в `main`, как и
раньше.

```
python tools/build.py            собрать корень из src/
python tools/build.py --check    проверить, что корень не разъехался с src/
```

Собирать и коммитить нужно **в одном коммите с правкой исходников**, иначе на
сайте окажется старая версия.

| `src/partials/tail-shop.html` | разметка каталога и подключение виджета |
| `src/partials/tail-checkup.html` | анкета на 595 вопросов: данные и логика, собирается скриптом |

| `src/assets/*.css` | стили, вклеиваются в `<style>` запросившей страницы |

### Шапка параметров страницы

Каждая страница в `src/pages/` начинается с блока между `---`:

| Поле | Зачем |
|---|---|
| `url` | адрес на сайте, он же canonical и адрес в карте сайта |
| `out` | куда положить собранный файл |
| `title`, `description`, `keywords` | мета-теги |
| `og_*`, `twitter_*` | превью в соцсетях; не задано — берётся из `title` |
| `css` | какой файл из `src/assets` вклеить |
| `head_extra`, `tail` | необязательные куски до `</head>` и после подвала |
| `updated`, `changefreq`, `priority` | строка в `sitemap.xml` |
| `robots` | по умолчанию `index, follow, …` |
| `sitemap: no` | не включать страницу в карту сайта |
| `magnet_*` | лид-магнит, см. ниже |

### Лид-магнит

Блок с формой, который отдаёт файл за имя и контакт. Страница объявляет поля
`magnet_*` в шапке и ставит в нужном месте тела слот `{{ magnet }}` —
вёрстку и скрипт сборщик подставит сам.

| Поле | Что это |
|---|---|
| `magnet_file` | путь к файлу в `/files/`. Нет файла — сборка падает |
| `magnet_goal` | своя цель Метрики для этого материала |
| `magnet_topic` | тема заявки: по ней видно, из какого материала пришёл человек |
| `magnet_id` | приставка к `id` полей формы, своя на каждой странице |
| `magnet_title`, `magnet_text` | заголовок и описание |
| `magnet_facts` | строчки списка, **через точку с запятой** — в числах бывают запятые |
| `magnet_button` | надпись на кнопке |

Заявка уходит в ту же «Диспетчерскую», что и форма с главной. Состав запроса
описан ниже.

## Анкета на 595 вопросов

`/checkup.html` — функциональная анкета по 22 системам организма. Её дают
записавшимся на консультацию **ссылкой вручную**: в меню её нет, в карте
сайта нет, в шапке стоит `noindex, nofollow`.

Так сделано намеренно. Заполнение занимает около часа — как публичный вход
с поиска анкета не работает, человек бросит на трёхсотом вопросе. А как
подготовка к разбору работает хорошо: Алина приходит на созвон, уже видя
картину. Публичный вход — короткий `/screening.html` на 18 вопросов.

Откуда вопросы: репозиторий `a6340374-stack/oprosnik`, там анкета жила
отдельной страницей на `github.io`. Тексты вопросов перенесены дословно.

**Данные вопросов правятся не руками.** `src/partials/tail-checkup.html`
собирается командой `python tools/build-checkup.py` из
`src/data/checkup-questions.json`: заголовки разделов чистятся от капслока
и нумерации, заголовки с переносом строки разбираются на заголовок
и пояснение. Правка вопроса — правка исходного JSON и пересборка.

Чем отличается от исходной версии:

- **Проценты считаются от отвеченного, а не от всех вопросов раздела.**
  В исходной версии наполовину заполненный раздел всегда выглядел
  благополучным: знаменателем было общее число вопросов. Здесь разделы
  без ответов в результат просто не попадают.
- **Открыт всегда один раздел,** вопросы остальных в разметку не попадают.
  595 вопросов по четыре кнопки — 2380 узлов, и исходная версия
  перерисовывала их все на каждый клик.
- **Поля и ответы закрыты от Вебвизора** (`ym-disable-keys`,
  `ym-hide-content`). В исходной версии Вебвизор писал ФИО, дату рождения
  и все 595 ответов открытым текстом.
- **Имя и дата рождения необязательны** и нужны только для подписи файла.
- **Черновик файлом.** `localStorage` привязан к браузеру, а Safari на iOS
  чистит его примерно через неделю без заходов на сайт. Для анкеты на час
  этого мало, поэтому рядом есть «Сохранить черновик файлом» и «Продолжить
  из файла» — переносится между устройствами и не протухает.

Ничего никуда не отправляется: серверной части у страницы нет, результат
человек скачивает файлом и присылает сам, если захочет.

## Что сайт присылает в «Диспетчерскую»

`POST https://alinaecosin.store/shop-api/site-lead`, JSON. Одинаково для
формы на главной и для любого магнита.

| Поле | Что в нём |
|---|---|
| `name` | имя, как ввели |
| `contact` | Telegram или телефон |
| `topic` | тема: выбор из списка на главной, название материала у магнита |
| `hp` | ловушка для ботов, у человека всегда пустая |
| `source_page` | страница: `/ramadan/menu.html` |
| `source_kind` | `form` или `magnet` |
| `source_id` | идентификатор магнита: `lead_magnet_menu`. У формы пусто |
| `source_title` | заголовок страницы, до 120 знаков |
| `source_campaign` | `utm_campaign` или `utm_source`, если были в адресе |

**Первые четыре поля приёмник читает давно, поля `source_*` — новые.**
Он разбирает тело через `body.get()` и лишние ключи молча игнорирует,
поэтому сайт шлёт их, не дожидаясь доработки на той стороне: ничего
не ломается, данные начнут сохраняться, как только приёмник их прочитает.

Зачем `source_page` при наличии `source_id`: один и тот же магнит стоит
на нескольких страницах. Меню на Рамадан отдаётся и с `/ramadan.html`,
и с `/ramadan/menu.html` — `source_id` у них одинаковый, а `source_page`
разный. Именно он показывает, какая страница приводит людей.

Пока приёмник не читает `source_*`, источник дублируется человекочитаемо
в конце `topic`: «Меню на Рамадан · /ramadan/menu.html». Когда структурные
поля заработают, приписку можно убрать — она задаётся одной функцией
`ecosinTopicSuffix` в `src/partials/metrika.html`.

**Если приёмник не ответил, файл всё равно отдаётся**, а человеку показывается
строчка с предложением написать в Telegram. Терять и контакт, и доверие из-за
упавшего сервера — худший из вариантов.

Файлы лежат в `/files/` и закрыты в `robots.txt`. Не ради секрета: прямую
ссылку всё равно можно переслать, и это нормально. Смысл в том, чтобы PDF не
попал в выдачу сам по себе и не перехватывал людей у страницы с формой.

Карта сайта собирается из этих полей. Руками `sitemap.xml` больше не трогать.

### Добавить страницу

1. Положить файл в `src/pages/` с шапкой параметров.
2. `python tools/build.py`.
3. При необходимости добавить ссылку в `src/partials/nav.html` или `footer.html`.

## Каталог магазина обновляется руками

Товары рисует виджет с alinaecosin.store. Робот Яндекса плохо исполняет
JavaScript, поэтому внутри `#ecosin-shop` лежит статическая копия каталога:
её видит поиск, а живому посетителю `widget.js` подменяет её на интерактивную
версию с корзиной.

Эта копия **не обновляется сама**. После любого изменения цен, остатков или
состава каталога:

```
python tools/build_shop.py
git add -A && git commit -m "Обновлён каталог" && git push
```

Скрипт правит **исходники**: карточки между маркерами `SHOP:STATIC` в
`src/pages/shop.html`, разметку между `SHOP:JSONLD` в
`src/partials/tail-shop.html`, дату в поле `updated`. Затем сам вызывает
`tools/build.py` и пересобирает корень. Руками внутри маркеров ничего не
писать — перезатрётся.

## Правила, которые легко нарушить по незнанию

**Не зашивать картинки в HTML через `data:base64`.** Так главная весила 796 КБ,
не кэшировалась и блокировала разбор страницы. Новые изображения — файлом в
`img/`, в WebP, с атрибутами `width`, `height` и `loading="lazy"` всем, кроме
первой картинки на экране.

**Не возвращать в `robots.txt` директивы `Host` и `Crawl-delay`** — Яндекс их
не поддерживает с 2018 года. Параметры ссылок склеиваются через `Clean-param`,
а не прячутся через `Disallow`: запрет обхода не передаёт вес на чистый адрес.

**Не писать ключевые слова в текст «для поиска».** В Яндексе переоптимизация
наказывается жёстче, чем недооптимизация: SEO-простыни в подвале и ключи в
точном вхождении ведут под фильтр Баден-Баден.

**Разметка Schema.org должна соответствовать тому, что видно на странице.**
Цены и наличие в JSON-LD берутся из того же API, что и каталог, — руками их
не править.

**Не править файлы в корне.** `index.html`, `shop.html`, `legal/*.html` и
`sitemap.xml` собираются из `src/`. Правка в корне живёт ровно до следующего
запуска сборщика и теряется молча. Если не уверены, разъехалось ли что-то, —
`python tools/build.py --check`.

## Состояние SEO

Сделано: статический каталог с разметкой `Product` для 20 товаров, картинки
вынесены из HTML (главная 793 КБ → 79 КБ), `robots.txt` с `Clean-param`,
подключён IndexNow, установлена Яндекс.Метрика 112475745 с целями.

Материалы под поиск: `/ramadan.html`, `/ramadan/menu.html`,
`/guides/fasting.html`, `/guides/detox.html`, `/guides/immunity.html`,
`/analizy.html` и шесть страниц наборов анализов в `/analizy/`.
Плюс `/screening.html` с опросником и `/kollegam.html` для специалистов.

Коммерческие страницы: `/about.html`, `/consultation.html`, `/health.html`,
`/pregnancy.html`. Карточки услуг на главной ведут на них, а не в общую
форму: человеку нужно сначала прочитать состав, а потом записываться.

**`/about.html` собрана из личной истории Алины** — болезнь сына, семь лет
ожидания второй беременности, дефициты, которые ей пропустили. История взята
из её же публичных постов в Telegram. Там есть сведения о здоровье её
ребёнка: она публиковала их сама, но **для сайта нужно отдельное её
подтверждение** — пост подписчикам и страница в поиске это разные вещи. На четырёх страницах стоят
лид-магниты.

**Схема добавок для детоксикации на сайт не выкладывается.** У Алины она
есть, и клиенткам она её даёт, но публичный протокол с брендами и дозами —
это назначение вслепую: желчегонное при камнях в желчном пузыре опасно,
часть трав нельзя при беременности. На странице про детокс сказано об этом
прямо, с уводом в личный разбор.

**Материалы школы MIIN** используются с разрешения заказчика, но брендинг
школы снят полностью: ни `miin.ru`, ни `miin_ankz`, ни ссылок на их курс
и внутренние материалы, ни чужого промокода ANKZ. Схема добавок из их
материала и ссылка на iHerb тоже не публикуются. Сертификаты MIIN на
главной — это дипломы самой Алины, они на месте и так и должно быть. Текста для робота на сайте
116 700 знаков против 15 800 до начала работы.

Витрина анализов собрана из данных проекта «Сдача анализов» (React + Vite,
живёт вне репозитория). Сам проект на отдельный домен решено не выносить:
в собранном виде робот видит в нём 55 знаков, весь контент рисует
JavaScript. Поэтому витрина пересобрана статикой здесь, а интерактивный
подборщик позже ляжет сборкой в `/analizy/podbor/`.

**Заказ анализов идёт через приложение Hello, Doc!** Ссылки в блоке
«Как заказать» — диплинки: на телефоне открывают приложение, на десктопе
страницу установки с QR. Из браузера заказать нельзя, и на страницах это
сказано прямо.

Два пути к заказу отличаются не ценой, а тем, кто собирает набор.
Вознаграждение сервиса выше за **подготовленные заказы** — те, что Алина
собирает в приложении Hello, Doc! Work. Поэтому первым на странице стоит
путь «собрать набор со мной», а самостоятельный заказ вторым.

### Цели Метрики

Отправляются через `window.ecosinGoal`. Обёртка молчит, если счётчик не
загрузился, — блокировщик рекламы у посетителя не должен ломать форму.

| Цель | Когда срабатывает |
|---|---|
| `lead_form` | заявка ушла на сервер и принята |
| `lead_messenger` | приёмник недоступен, человека увели в мессенджер |
| `lead_magnet` | получен любой материал за контакт |
| `lead_magnet_menu` | меню сухуров и ифтаров |
| `lead_magnet_fasting` | методичка об интервальном голодании |
| `lead_magnet_detox` | методичка по детокс-питанию |
| `screening_done` | человек дошёл до результата опросника |
| `checkup_done` | человек дошёл до результата функциональной анкеты |
| `telegram_click` | клик по ссылке на Telegram |
| `whatsapp_click` | клик по WhatsApp |
| `phone_click` | клик по номеру телефона |
| `shop_open` | переход в магазин |

Каждая цель должна быть заведена в интерфейсе Метрики как «JavaScript-событие»
с тем же идентификатором — иначе событие просто никуда не попадёт. Рост
`lead_messenger` означает, что приёмник заявок на alinaecosin.store падает.
